# Component information overlay research

Researched the owner’s request for a component’s designation, name and specific purpose on mouse-over, shown where control instructions currently appear. Traced shared pointer coordinates, crosshair targeting, the instructions DOM and timers, room raycasts, installed asset/valve registers, catalogue purposes, model identification, and static geometry merging. The catalogue already contains much of the required prose; some installed-valve descriptions remain generic and need explicit functions in the canonical register. The requested PL3-BT1-IV1 now exists in the current working tree as the jacuzzi tank’s make-up isolator.

Saved findings, source links, a proposed implementation and acceptance checks in `doc/research/component-information-overlay.md`. Recommended the existing printed plant tag rather than a new serial scheme; one shared overlay presenter; free-pointer and centre aiming through the shared controls; read-only metadata; explicit handling of merged ownership and hidden pick proxies; a dev0 prototype before the jacuzzi room. Cross-scene inspection is identified as a follow-up rather than claimed as part of local raycasting. Recorded the unimplemented feature in TODO.md and the research in the changelog. No runtime code, save shape or version changed. Formatting and diff checks validate the documentation; implementation tests have not been run for this research-only change.

The owner extended the research with narrative popups for opening and closing valves, pressing buttons and switching off machines. Added the requested sentence patterns, canonical tag/name examples, transient HUD priority and queue recommendations, and event integration research. World action descriptions already know before/after and player/console attribution; reusable parts expose physical press events, including presses that have no effect without power. The proposal correlates these to avoid duplicate popups and distinguishes completed operations from actuator commands or failed requests. Added acceptance checks and expanded the existing TODO and changelog entry. Documentation only; no runtime behaviour implemented.
