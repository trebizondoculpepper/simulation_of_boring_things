# 114: the plan, and how the work is split

The brief is `doc/prompts/114-aqualis-dosing-controller.md`. The owner put this session in charge of the Dr Aqualis project (2026-10-31) and asked for the work to be split among agents. This plan fixes the shapes the parts pass one another (`src/game/plant/aqualis-types.ts`), so that each part can be built and tested on its own against them; the parts then meet in the display model and a closed-loop test, which this session does itself.

Then, as the brief orders: the dev room (dev58) on the rig with the cabinet, the cabinet as a block in a plant room's schematic, the alarms on the annunciators and both control rooms, and installation for the Olympic and Lounge pools, where it takes over from `water-treatment.ts`'s unseen controller.

## Rules every agent keeps

- Build against `aqualis-types.ts`; do not change it. A shape that will not do is reported back, not worked round.
- Pure logic has no DOM or Three.js and is tested beside it (`*.test.ts`, from `vite-plus/test`); anything over about 1.5 s in a `*.slow.test.ts`.
- Write only the files named for the part (and their tests, and a bench registration where named). Leave `CHANGELOG.md`, `TODO.md`, `package.json` and `package-lock.json` to this session.
- Commit in the agent's own worktree; do not push. Report the branch and commit.
