The visual specification is clear, but the plan needs a firmer integration and performance design before implementation:

- **The hold clock breaks the stated budget.** At 1,000×, one lab minute passes every 0.06 real seconds. A clock keyed to the lab minute would therefore redraw about 17 times a second: roughly 3.3 million texels/s for one 512 × 384 screen. The component budget is 300,000 active texels/s, with a separate update cost limit ([component-bench.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/toolkit/gallery/logic/component-bench.ts:152)). Show coarser progress or use a much smaller changing texture, then measure the assembled console.

- **The kit has no specified path into the existing touch system.** `touch-surface.ts` already maps a ray hit to screen pixels, routes it through the common controls, handles the bezel, plays touch sounds, and owns texture updates ([touch-surface.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/toolkit/components/industrial-control/views/touch-surface.ts:25)). It expects a `UiNode` tree. The plan should say whether to adapt that host for immediate-mode screens or reuse `UiNode` with an Aero theme. A separate `hitRegion` alone does not make the screens usable in the game.

- **“Everything shown” is too vague for a redraw key.** The scenario includes changing doses, progress, outcome and challenge state; the chemical screen includes selection and scroll position; controls have pressed and disabled states. Define a typed view model and key per screen, derived once per world step, so a missing field cannot leave stale pixels. The current Hall 4 desk reads several independent callbacks from hall state ([hall-4-chemistry.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/toolkit/gallery/rooms/museum/hall-4-chemistry.ts:500)).

- **The proposed tests stop before the risky boundary.** Layout and `RedrawGate` tests will not catch wrong UV orientation, touching a disabled arrow, clipped text, or a button whose drawn rectangle differs from its hit rectangle. Add a small host integration test and a visual check at the desk’s actual size. The current face is only 2.0 × 0.75 m ([museum-chemistry-parts.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/toolkit/components/plant/views/museum-chemistry-parts.ts:282)).

- **Branding and text need an explicit contract.** `drawMakerStrip` should accept the existing brand record and mark, rather than introduce hand-written maker artwork or text; the current desk is a Penfold product ([museum-chemistry-parts.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/toolkit/components/plant/views/museum-chemistry-parts.ts:277)). Test wrapping with the actual loaded font and screen width, since an injected test measure alone cannot establish that the chemical descriptions fit.

- **The performance claim counts only one screen.** Three simultaneous redraws are 589,824 texels per update, before any other display. Register the finished console in the component benchmark and measure idle uploads, active uploads, drawing work and update time, rather than treating arithmetic for one canvas as a pass.
