**The plan needs a clearer host contract before implementation.** The pure state and hit tests are a sound starting point, but several behaviours depend on code outside the proposed reducer:

- **Press feedback does not match the current touch API.** The shared touch surface sends `UiRoot.tap()`, which releases its pressed state after the theme’s hold; it does not deliver a screen release event ([touch-surface.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/toolkit/components/industrial-control/views/touch-surface.ts:339), [node.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/ui2d/node.ts:261)). Use that mechanism for the glow, or specify how a release reaches `DosingConsoleState`. A 0.15 s timer in the reducer alone cannot clear it.

- **“Each press is two redraws of one screen” is too strong.** Selecting a chemical changes both the Chemical and Dose screens; starting a card changes the Scenario and Dose screens. Define each screen’s key from the values it actually paints, and test those cross-screen changes. Keep texture uploads behind a changed key, as the existing touch surface does ([touch-surface.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/toolkit/components/industrial-control/views/touch-surface.ts:317)).

- **The state can outlive the screen it describes.** The engine automatically leaves a win after eight real seconds, while `confirmReset`, `pressed`, and the chooser live separately. Specify how the host clears or reconciles them when the engine changes mode. In particular, a RESET dialog must block hits on the controls behind it; its hit tests need an explicit modal rule.

- **Effects need an authoritative result.** The UI can show “No doses left,” but only the engine can decide whether a dose was accepted. Have the host pass acceptance or refusal back so the deny sound and displayed count agree. Test a dose at par and immediately after a win or failure, not just the reducer’s output.

- **The proposed hit tests omit the 3D input boundary.** The shared touch code maps UVs to pixels and handles a ray striking the coplanar frame before the screen ([touch-surface.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/toolkit/components/industrial-control/views/touch-surface.ts:339), [touch-surface.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/toolkit/components/industrial-control/views/touch-surface.ts:360)). Add an integration test for both paths, plus the physical DOSE button, so correct rectangle tests do not mask an unreachable control.

- **Migration from the existing Hall 4 state is unspecified.** `Hall4State` already owns card selection, active card, dose delivery, and swimmer state ([museum-4-lab.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/game/plant/museum-4-lab.ts:872)); the hall currently runs that session locally ([hall-4-chemistry.ts](/Users/salimfadhley/workspace/simulation_of_boring_things/src/toolkit/gallery/rooms/museum/hall-4-chemistry.ts:155)). State which fields the new engine supersedes and how the other hall instruments read the new session. Otherwise the screens can disagree with the meters and mimic.
